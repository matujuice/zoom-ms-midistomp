# MIDISTOMP v1.1 brief (draft 2)

## Goal

Turn the Zoom MultiStomp into a performance instrument with **parallel
routing** (Mixer Mode), new custom effects built for it, and later a
Performance Mode with macros.

**Test project:** an Octatrack-style transition. Capture a loop, crossfade to
it, add stutters/rolls and a low-end cut on the loop bus, while the live bus
gets a washout. Both buses merge at the end into a master high-pass and a
stereo mastering chain. This needs parallel routing, which is the main
challenge of this release.

## Words used in this brief

| Term | Meaning |
|---|---|
| **Effect View** | The normal screen: effect covers in a row; enter one to tweak its knobs. |
| **Effect Chain screen** | The screen where effects are ordered. In v1.1 it is also where routing is set. |
| **Pre** | Effects before the split (Main bus, before `[ROUTE]`). |
| **Bus A / Bus B** | The two parallel buses between `[ROUTE]` and `[MIX]`. A is the top row, B the bottom row on the Effect Chain screen. |
| **Post** | Effects after the merge (Main bus, after `[MIX]`). |
| **`[ROUTE]` / `[MIX]`** | The split and merge nodes. Drawn on screen like effects, with their own knob pages, but they **do not use effect slots**. |

**Direction is always right to left**, like the stock screen and the jacks:
input on the right, output on the left. Written as a chain:

```
OUTPUT ← Post ← [MIX] ← Bus A / Bus B ← [ROUTE] ← Pre ← INPUT
```

## Firmware targets

The MS-50G and MS-60B are the same hardware; the only hardware difference in
the family is the input. All pedals have stereo outputs.

| Build | Pedals | Input modes |
|---|---|---|
| **Mono input** | MS-50G, MS-60B | Serial, Parallel |
| **Stereo input** | MS-70CDR | Serial, Mono Serial (sums L+R), Parallel, Split (L → A, R → B) |

Both builds run effects in stereo and have the same 6 effect slots. Options
that can't work on the mono build (Split, Mono Serial) are removed from the
menus, not just greyed out.

> **Challenge (porting):** carry MIDI CC, clock, the MIDI menu, tempo screen,
> HOLD FOR and combos over to the stereo input build. Today every build comes
> from the MS-50G 3.10 OS. Find out whether the MS-70CDR should run that OS
> with stereo input enabled, or whether the patches must be ported to the
> MS-70CDR OS. Test hardware for both builds is now available.

## Phase 1: Custom effects (ZDLs)

True stereo in and out wherever possible. All parameters go through the normal
parameter path, so MIDI CC (and later Performance Mode macros) can reach them.

- **Looper:** synced capture, internal crossfade between live and loop, beat
  rolls/stutters, its own built-in low-end cut is optional (a Filter on the
  loop bus does the same job).
- **Filter:** multi-mode, at least a high-pass for low-end cleanup.
- **Washout:** based on the existing Washout delay; exposes its controls as
  normal parameters.
- **Stereo Compressor/Limiter:** for the end of the chain.

> **Challenge (looper memory) — must be solved:** the looper must hold
> **8 bars from 100 to 200 BPM** (8 bars at 100 BPM = 19.2 s).
> One effect slot gets about 4 s of mono audio. Rough sizes for 19.2 s:
>
> | Format | Size |
> |---|---|
> | stereo, 32-bit | 6.8 MB |
> | stereo, 16-bit | 3.4 MB |
> | mono, 16-bit | 1.7 MB |
> | stereo, 8-bit µ-law | 1.7 MB |
> | mono, 8-bit µ-law | 0.85 MB |
>
> Free RAM measured on the mono build: about 2.8 MB in five pieces, the
> largest about 1.6 MB. Options to evaluate: the firmware hands the looper a
> large free buffer, the looper takes the memory of two slots, µ-law or
> 16-bit storage, mono sum for the loop only. Free RAM on the stereo build
> must be measured again (RAM canary test).

> **Challenge (tempo changes while a loop plays):** options, cheapest first:
> 1. **Slice playback:** the loop is cut into beat slices that are retriggered
>    on the clock. Pitch stays the same, it follows any tempo, small artifacts
>    at slice edges. Same machinery as the rolls/stutters. **Recommended.**
> 2. **Varispeed:** play faster or slower, pitch changes with it. Very cheap.
> 3. **Real time-stretch:** best sound, likely too heavy alongside the other
>    effects. Evaluate only if 1 isn't good enough.

Loops are lost on a patch change. This is expected: the transition happens
inside one patch.

## Phase 2: Mixer Mode (routing engine)

The audio chain is rebuilt as:

```
OUTPUT ← Post ← [MIX] ← Bus A ← [ROUTE] ← Pre ← INPUT
                      ↖ Bus B ↙
```

Any of the 6 effects can sit in Pre, Bus A, Bus B or Post. A dry path is just
an empty bus (or a bus with its effects off).

### Effect Chain screen (reworked)

The two nodes are fixed markers that split the screen into zones. Effects
right of `[ROUTE]` are Pre, effects left of `[MIX]` are Post, effects between
them are on Bus A (top row) or Bus B (bottom row).

| Control | Normal | With an effect lifted |
|---|---|---|
| Left knob | select effect | move it left/right; crossing `[ROUTE]` or `[MIX]` moves it between Pre, buses and Post |
| Middle knob | exit | exit |
| Right knob | — | move it up/down between Bus A and Bus B (only between the nodes) |

The nodes themselves can't be lifted or moved.
*Needs photos of the stock Effect Chain screen to fit the layout to the real
display.*

### Effect View

Covers are sorted right to left: Pre, `[ROUTE]`, Bus A, Bus B, `[MIX]`, Post.
Every effect between the nodes shows an **A** or **B** tag so parallel effects
don't read as serial. All stock button presses work as before. `[ROUTE]` and
`[MIX]` open like any effect to show their knob pages.

### Node knob pages

Page 1 is for playing, page 2 for setup.

**`[ROUTE]`**

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Send** (A ↔ B; centre = both full) | Input Level | Mode |
| 2 | Bus A Level | Bus B Level | — |

**`[MIX]`**

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Blend** (A ↔ B) | Master Level | Output Mode (Stereo / Mono / Split: A → L, B → R) |
| 2 | Bus A Level | Bus B Level | Phase Invert (Bus B) |

- Send and Blend are the performance controls. Per-bus levels are trims for
  setup, on page 2.
- If Send and Blend point at opposite buses (e.g. send only to A, blend only
  from B), the output is silent. Show a small badge on `[MIX]` when that
  happens.

> **Challenge (crossfade curves):** pick curves and levels with no volume dip
> or bump in the middle. Send should keep both buses at full level at the
> centre (true parallel). Blend should keep the perceived level constant
> across the sweep.

> **Challenge (summing headroom):** adding two buses can clip. `[MIX]` needs
> headroom or a safety limiter.

> **Challenge (bus latency):** if one bus delays the sound more than the other
> (e.g. pitch effects), the sum will comb-filter. Find out whether bus delays
> can be measured and matched; Phase Invert helps the user check.

> **Challenge (DSP load):** parallel routing doesn't lower the processing
> load and stereo effects cost about twice as much as mono. Measure whether 6
> effects plus routing fit, and what happens when they don't.

### Serial modes

When `[ROUTE]` is set to a Serial mode, `[MIX]` and the A/B rows disappear
and all effects run in one line in this order, right to left: Pre, Bus A,
Bus B, Post. Each effect **remembers its bus**, so switching back to Parallel
restores the layout.

### Smart Mono Warning

Show a badge on any mono-input effect that collapses a stereo or Split
signal.

### Saving

> **Challenge (patch storage):** bus assignments, node settings and mode must
> be saved with each patch. Find where they can live. Compatibility with
> Zoom's editor or Effect Manager is not a goal for now.

Clicks when changing routing live are acceptable, as with changing effects
live.

### MIDI

Every `[ROUTE]` and `[MIX]` parameter gets a CC (Send, Blend, levels, modes),
chosen so it doesn't clash with the current CC chart or the stock CC 74/75.
These are also the hooks Performance Mode will use.

## Phase 3: Performance Mode (to be scoped later)

Not designed yet. Starting points for that design:

- Macros drive parameters through the MIDI CC parameter path.
- Open questions: entering/leaving the mode and how the screen shows it,
  living alongside HOLD FOR and the combos, saved per patch or global,
  min/max range per macro target.
- Timed drop-outs and resets on the downbeat: what drops out, for how long,
  what triggers it, where the downbeat comes from without a MIDI Start.
