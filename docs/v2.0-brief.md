# MIDISTOMP v2.0 brief (draft 33)

## Goal

Turn the Zoom MultiStomp into a performance instrument with **parallel
routing** (Mixer Mode), new custom effects built for it, and Perform mode
(every control assignable, with follow actions on the musical grid).

**Test project:** an Octatrack-style transition. The loop bus captures a loop
and adds a low-end cut and rolls/stutters. The live bus stays dry. Both buses
merge into the Post (master) chain: washout, master high-pass and stereo
mastering. This needs parallel routing, which is the main
challenge of this release.

## Words used in this brief

| Term | Meaning |
|---|---|
| **Effect View** | The normal (home) screen: one effect at a time, scrolled with the left/right keys, with its knobs. |
| **Effect Chain screen** | The screen where effects are ordered. In v2.0 it is also where routing is set. |
| **Pre** | Effects before the split (Main bus, before `[ROUTE]`). |
| **Bus A / Bus B** | The two parallel buses between `[ROUTE]` and `[MIX]`. A is the top row, B the bottom row on the Effect Chain screen. |
| **Post** | Effects after the merge (Main bus, after `[MIX]`). |
| **`[ROUTE]` / `[MIX]`** | The split and merge nodes. Drawn on screen like effects, with their own knob pages, but they **do not use effect slots**. |

**Direction is always right to left**, like the stock screen and the jacks:
input on the right, output on the left. Written as a chain:

```
OUTPUT ← Post ← [MIX] ← Bus A / Bus B ← [ROUTE] ← Pre ← INPUT
```

## Firmware targets

From v2.0 every pedal runs **one build, made from Zoom's MS-70CDR 2.10 OS**
(decided 2026-10-15). The MS-50G and MS-60B run that OS as a 70CDR with only
the L input plugged in (tested by Luca), and the OS already goes mono when
only L is plugged. v1.1 stays the last release on the MS-50G 3.10 OS.
Port plan: `docs/ms70cdr-base.md`. Why not stereo on the MS-50G OS:
`docs/ms70cdr-port.md`.

All pedals have stereo outputs. Input modes depend on the pedal's input:

| Pedal input | Pedals | Input modes |
|---|---|---|
| **Mono** | MS-50G, MS-60B | Serial, Parallel |
| **Stereo** | MS-70CDR | Serial, Mono Serial (sums L+R), Parallel, Split (L → A, R → B) |

The OS can't tell the pedals apart (the AXR4 probe found no reliable sign),
so a setting says which input the pedal has (**PEDAL INPUT: MONO / STEREO**,
default MONO). With MONO, Split and Mono Serial are removed from the menus,
not just greyed out. Effects run in stereo on every pedal, 6 slots.

## Looper architecture (decided 2026-10-15)

Luca picked the **Hybrid**. Options weighed and numbers:
`/mnt/project-files/plan/v2.0-looper-architecture.md` (project files).

- **Audio in a ZDL** (effects pack, C with host tests): record, play, Roll,
  slice playback. Placed on a bus like any effect, so it takes one of the 6
  slots and Mixer Mode needs no special case. One looper per patch.
- **Firmware looper services**, in a new block with its own address and
  magic (the transport block contract at `0x1181FF00` is not touched):
  1. **Big buffer:** free RAM regions 3 and 2 (`0xC0636980`-`0xC07CFFFF`,
     `0xC01ADAD4`-`0xC01FFFFF`) plus the looper's own 705 KB slot block,
     about 2.72 MB. The ZDL treats it as empty whenever its arena is new.
  2. **Trigger instead of bypass:** with the looper under the cursor, the
     footswitch and its on/off CC bump a press counter instead of flipping
     (same kind of hook as v0.6 MOMENTARY). Press, double press and
     quantize are decided in the ZDL.
  3. **State out:** the ZDL publishes empty / recording / playing /
     stopped and the bar in the loop; the firmware shows it on the Effect
     View and the LED.
  4. **Grid:** the transport block as it is; Perform mode reads the same
     counters.
- Rejected: **Effect** alone (8 s of memory, shows OFF while playing, no
  state on screen); **Firmware** block (all DSP in hand-written assembly
  in the unmapped audio loop, no host tests).

**Loop format:** 12-bit block-float (one shared exponent per 16 frames,
about 3.06 B per stereo frame), noise about 72 dB under the signal. Luca
A/B'd it against 16-bit on his own loop and picked it. Stereo or mono is
chosen when recording starts, from BPM x Length (20.1 s stereo, 39.5 s
mono; tempo range 40-250 BPM):

| Length | Stereo | Mono | Doesn't fit |
|---|---|---|---|
| 1-2 bars | any tempo | — | — |
| 4 bars | 48 BPM and up | 40-47 BPM | — |
| 8 bars | 96 BPM and up | 49-95 BPM | below 49 BPM (records 4 bars, shown on screen) |

These numbers come from the RAM test on the MS-60B (MS-50G 3.10 OS);
measure again on the MS-70CDR OS (port step 3).

**Order** (Luca: full looper first, no throwaway shell):
1. **Full Looper ZDL** with everything above. Until step 2 exists it runs in
   its own arena (short loops) and takes on/off flips as presses (a
   switched-off ZDL keeps running and is heard). Watch the ZDL boot limit
   (30.9 KB boots, 36 KB hung).
2. **Looper services** in the firmware, and the boot-size limit if the
   looper needs it.
3. **Mixer Mode**, then **Perform mode**.

Each step is scoped with Luca before it is built.

## Phase 1: Custom effects (ZDLs)

True stereo in and out wherever possible. All parameters go through the normal
parameter path, so MIDI CC and Perform mode can reach them.

- **Looper** (details below). **Base:** the abandoned looper project from
  the effects pack (the project knows where it is). Scrub and GridDly in the
  pack already run a 7.9 s 16-bit buffer and tempo-synced loops, so they are
  the next best reference.
- **Filter:** reuse **Sweep** from the pack instead of a new effect. Its
  LP / BP / HP / NTCH types with Depth 0 are already a static resonant
  filter, and it only runs the engine Type picks (one filter, cheap).
  Needs a stereo version. Measure its load next to the others.
- **Washout:** build it as a new **WASH** engine in **GridDly**. GridDly as
  it is gives clean, separate echoes, not a wash: a washout smears the
  repeats into a reverb-like cloud, which needs diffusion (all-pass
  filters) inside the feedback loop. GridDly already has the long memory,
  tempo sync, feedback past 100 and Tail, so adding the diffusion is the
  cheapest route. Needs a stereo version.
- **Mastering Limiter:** new, stereo linked, for the end of the chain. A
  loudness limiter (maximizer), not just a peak catcher: it pushes the mix
  up and holds it under a ceiling. Knobs: **Gain** (how hard it is pushed),
  **Ceiling** (default -0.1 dB), **Release** (with an AUTO setting). It may
  look ahead a few ms to catch peaks cleanly; that delay is harmless after
  `[MIX]`. A compressor is a separate effect, later (not in v2.0).

> **Challenge (stereo pack effects):** most effects in the pack were built
> on the MS-60B and are mono. Sweep, GridDly and the looper need stereo or
> dual mono versions for the stereo routing to pay off; the rest can follow.

### Looper

| Control | What it does |
|---|---|
| **Footswitch** | press: record (when empty) / stop / play; double press: delete; hold: nothing (see below) |
| **Length** knob | loop length, 1 to 8 bars |
| **Quant** knob | when recording starts and stops: **LOOP** (default) snaps both to the loop-length grid, so with 4 bars it waits for the next 4-bar line, records 4 bars, then plays; **BAR** snaps to the next bar; **OFF** starts at once |
| **Roll** knob | OFF, 1/2, 1/4, 1/8, 1/16, 1/32 (no triplets). **Latched:** any setting but OFF rolls until the knob goes back to OFF. It works as an automatic, perfectly quantized beat repeat: the roll **starts on the next bar line** and repeats the **first slice of that bar** (at 1/8: its first 1/8). Turning the knob while rolling multiplies the repeats (1/4 → 1/8 → 1/16 ...), each change landing on the grid |
| **Mix** knob | crossfade between live and loop, for Serial mode. In Parallel mode keep it at 100 % wet and use the Crossfade on `[MIX]` |

**Footswitch, step by step** (every action waits for the Quant grid):

| State | Press | Double press | Hold |
|---|---|---|---|
| Empty (silent) | wait for the grid, record Length bars, then play | — | nothing |
| Playing | stop at the next grid line (loop is kept, output silent) | delete the loop; back to Empty | nothing |
| Stopped | play again at the next grid line | delete the loop; back to Empty | nothing |

- **Press only records when the loop is empty.** To record a new loop,
  delete the old one first.
- **Stop is the looper's own stop, not a bypass.** A bypassed effect passes
  the dry signal, so bypassing a 100 % wet looper on a parallel bus would
  suddenly double the live sound. (The same applies to any 100 % wet effect
  on a bus.)
- **Stopping with Crossfade on the loop bus means silence.** Bring Crossfade back
  towards the live bus first (or give the stop a follow action).
- **Double press costs nothing in timing:** every action waits for the grid
  anyway, so there is time to tell a single press from a double one. Only
  with Quant OFF does a single press wait for the double-press window
  (about 300 ms).
- **Before the first recording and while recording,** there is no loop to
  play, so only the dry part of Mix is heard: Mix 100 = silence, Mix 50 =
  dry signal at the Mix 50 level.
- **MIDI:** the looper's existing on/off CC (14, 24, ... 64 by position)
  acts as its footswitch: a value of 64 or more is a press. Two presses in
  the double-press window delete. This works from any screen.

**Bar 1:** MIDI Start when a MIDI clock runs. Without one, bar 1 is the
moment you press the footswitch, so the first recording starts right away and
sets the grid.

> **Challenge (footswitch):** on the stock pedal the footswitch only turns
> the effect on screen on or off; the effect itself just sees that it was
> switched. A looper needs a trigger instead (press = capture) and must keep
> running. This needs a firmware hook: with the looper on screen, the
> footswitch sends a trigger to it instead of bypassing it. A second problem
> is reach: during a transition you need the looper's footswitch and Crossfade on
> `[MIX]`, which are on different screens. Perform mode puts them together;
> outside it, Crossfade is reached from the Effect Chain screen or by MIDI CC.

> **Challenge (looper memory) — must be solved:** the looper must hold
> **8 bars from 100 to 200 BPM** (8 bars at 100 BPM = 19.2 s).
> One effect slot's memory is about 705 KB: about 4 s of mono 32-bit audio,
> or 7.9 s of mono 16-bit (what Scrub and GridDly in the pack use). Rough
> sizes for 19.2 s:
>
> | Format | Size |
> |---|---|
> | stereo, 32-bit | 6.8 MB |
> | stereo, 16-bit | 3.4 MB |
> | mono, 16-bit | 1.7 MB |
> | stereo, 8-bit µ-law | 1.7 MB |
> | mono, 8-bit µ-law | 0.85 MB |
>
> Free RAM measured on the mono build: about 2.8 MB in five pieces, the
> largest about 1.6 MB. Options to evaluate: the firmware hands the looper a
> large free buffer, the looper takes the memory of two slots, every slot gets
> more memory (bigger per-slot blocks from the free RAM), µ-law or
> 16-bit storage, mono sum for the loop only. Free RAM on the stereo build
> must be measured again (RAM canary test).
>
> **Decided:** see "Looper architecture" above (big buffer of about 2.72 MB,
> 12-bit block-float, stereo or mono by tempo and Length).

> **Challenge (tempo changes while a loop plays):** options, cheapest first:
> 1. **Slice playback:** the loop is cut into beat slices that are retriggered
>    on the clock. Pitch stays the same, it follows any tempo, small artifacts
>    at slice edges. Same machinery as the rolls/stutters. **Recommended.**
> 2. **Varispeed:** play faster or slower, pitch changes with it. Very cheap.
> 3. **Real time-stretch:** best sound, likely too heavy alongside the other
>    effects. Evaluate only if 1 isn't good enough.

Loops are lost on a patch change. This is expected: the transition happens
inside one patch.

## Phase 2: Mixer Mode (routing engine)

The audio chain is rebuilt as:

```
OUTPUT ← Post ← [MIX] ← Bus A ← [ROUTE] ← Pre ← INPUT
                      ↖ Bus B ↙
```

Any of the 6 effects can sit in Pre, Bus A, Bus B or Post. A dry path is just
an empty bus (or a bus with its effects off).

### Effect Chain screen (reworked)

**Official design:** the clickable mockup [`mixer-ui-mockup.html`](mixer-ui-mockup.html)
(open it in a browser). Where this section and the mockup disagree, the
mockup wins.

**Stock screen today** (from photos and the MS-70CDR manual, p.13): one row
of 3 effect covers, scroll arrows at the sides, the output jack icon at the
left end of the chain. Turn knob 1 to select, press knob 1 to "lift" (a crane
animation raises the cover into the space above the row), turn to move,
press to drop. Press knob 2 to exit. Effects that are OFF are drawn dotted.

**New screen (128 × 64):**

- The crane and the lift space are gone. Rows: title 0-8, Bus A covers
  11-28, Pre/Post covers 21-38, Bus B covers 31-48, hints at row 50,
  softkeys 56-63.
- Covers are the stock 33 px wide but 18 rows tall instead of 19 (no padding
  above the name), so the cursor border never touches the title bar or the
  cover above or below. Name on 2 lines of 5 characters, 2-px bottom edge,
  checker border when OFF.
- Pre effects on the right and Post effects on the left sit on the centre
  line; between them Bus A sits on top and Bus B below.
- `[ROUTE]` and `[MIX]` are square boxes (stock EXIT style) as wide as a cover and as tall as both bus
  rows, with their names spelled out.
- Scrolling is stock: 3 columns on screen, the cursor's column always in the
  middle. A bus column holds its Bus A and Bus B effect one above the other.
  Gaps are 4 px, 8 px where lines split or join.

The nodes split the chain into zones. Effects right of `[ROUTE]` are Pre,
effects left of `[MIX]` are Post, effects between them are on Bus A or B.

| Control | Browsing | Item selected |
|---|---|---|
| Knob 1 turn | move the cursor | move the item; past `[ROUTE]` or `[MIX]` it changes zone |
| Knob 1 press | `SELECT` | `DROP` |
| Knob 2 press | `EXIT` | nothing (effects: softkey `DELETE` with a small `HOLD` hint; nodes: blank softkey) |
| Knob 2 long press (0.6 s) | — | effects only: softkey `DELETE?`, then a knob 2 press deletes; anything else cancels |
| Knob 3 turn | — | effect on a bus: Bus A ↔ Bus B (`▲▼` hint); `[ROUTE]`: Mode; `[MIX]`: Output Mode (the softkey shows the value) |
| Knob 3 press | `OPEN` (knob pages) | `OPEN` (also drops the item) |
| Cursor ◄ ► hold | add an effect on that side of the cursor, in the same zone (6 max) | |
| Cursor ◄ ► short press | nothing | |
| Cursor ▲ ▼ | change the type of the effect under the cursor | |

Delete is a long press with a confirmation, so pressing knob 2 twice to exit
can never delete an effect. After a delete the cursor goes to the next item in
the signal.

"Item" means an effect or a node. Nodes move only left/right: moving `[ROUTE]`
or `[MIX]` past an effect moves that effect between Pre/Post and the buses.
Nodes never change rows, and `[ROUTE]` always stays right of `[MIX]`. Opening
any item (knob 3 press = OPEN) shows its knob pages, the same screen as in Effect View. EXIT
returns to the Effect Chain screen. Nodes and jacks open only from here.

**Cursor and selection** (replaces the lift): the cursor is a 1-px border
around the item. A selected item is drawn like the stock CHO choice: the cover filled (inverted) plus a separate thin square frame with a 1-px gap. `[ROUTE]` and `[MIX]` use the stock EXIT box style (square corners, 1-px line, no thick bottom) so they differ from the rounded effect covers; selected, they get the same inverted + frame look. The `{}` hint
over knob 1 shows it turns; the `▲▼` hint over knob 3 shows while a bus
effect is selected (drawn like the stock `◄►` arrows, turned).

**Jacks:** IN at the right end, OUT at the left end, each in its own column.
They are the stock plug icon copied pixel for pixel (stub, ridged body, ring
with insulator bar, rounded tip; OUT is its mirror), with a 1-px cable and no
text. One plug per channel, L above R as printed on the case. The cursor can
land on IN and OUT: OPEN shows their knob pages (Input Level; Master Level, each with an R knob in Split); they never move or get selected. While the safety limiter is
reducing gain, a small `LIMIT` tag shows over the OUT plugs. PEDAL INPUT
sets the IN side. OUT shows 2 plugs with Output Mode Stereo or Split (even
from a mono input, since both jacks carry it), 1 with Mono.

**Signal lines:** one line per channel (mono: one line, stereo: two lines
2 px apart). Lines run outside the boxes: they split in the gap **before**
`[ROUTE]` and join in the gap **after** `[MIX]`. Where two lines cross without
joining, one hops over the other.

| `[ROUTE]` Mode / Output Mode | Lines |
|---|---|
| Parallel | Pre → split before `[ROUTE]` into Bus A and Bus B → join after `[MIX]` → Post |
| Serial | one line (or one stereo pair) through every effect, no `[MIX]` |
| Mono Serial | as Serial, but L and R join into one line just before `[ROUTE]` |
| Split input | the L line goes to Bus A only, the R line to Bus B only |
| Split output | Bus A goes to the L line, Bus B to the R line |
| Output Mono | one line after `[MIX]` (in Serial: after the last bus effect) |

OFF effects are drawn dotted; the lines stop at their edges like any cover.

### Effect View

Effects are sorted right to left: Pre, Bus A, Bus B, Post. The knob pages of
an effect on a bus show **A** or **B** as a filled tag at the right of the tab
row (not in Serial modes). All stock button presses work as before. Effect View
shows only effects, as stock: `[ROUTE]`, `[MIX]`, IN and OUT do not appear
here. They open only from the Effect Chain screen. To crossfade while playing,
use MIDI CC 86 (or Perform mode, later).

### Node knob pages

Page 1 is for playing, the other pages for setup.

Every level (Input, the bus levels, Master) goes **0-150, 100 = unity**,
like stock effect levels, so a quiet chain or bus can be boosted a little
(150 is about +3.5 dB). The safety limiter after Master keeps a boost from
clipping the jacks.

**`IN`** (the IN jack, Luca 2026-10-18): the start of the chain, before Pre,
in every mode. It opens like a node but never moves.

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Input Level** (with Split input: **Input L**) | — (with Split input: **Input R**) | — |

With Split input, knob 1 sets the left side and knob 2 the right side. Back in
normal mode knob 1 drives both sides again. With PEDAL INPUT MONO, Split input
is unavailable, so IN never shows L/R.

**`[ROUTE]`**

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Send** (A ↔ B; centre = both full) | — | Mode (Serial / Parallel / Split / Mono Serial) |
| 2 | Bus A Level | Bus B Level | — |

**`[MIX]`**

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Crossfade** (A ↔ B) | Output Mode (Stereo / Mono / Split: A → L, B → R) | Crossfade Curve |
| 2 | Bus A Level | Bus B Level | Phase Invert (Bus B) |
| 3 | **Mute A** (Off / On) (Luca 2026-10-18) | **Mute B** (Off / On) | **Solo** (Off / A / B) |

**`OUT`** (the OUT jack, Luca 2026-10-18): the end of the chain, after Post,
in every mode. It opens like a node but never moves.

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| 1 | **Master Level** (with Output Mode Split: **Master L**) | — (with Output Mode Split: **Master R**) | — |

With Output Mode Split, knob 1 sets the left side and knob 2 the right side
(same rule as IN).

Input R and Master R cost one saved byte each. Patch room is tight: route A
has 6 spare bytes (byte 17 of each slot block), and Output Mode, Mute and Solo
already pack into the Mode byte's high bits.

The safety limiter (automatic, no setting) is the very last thing before the
jacks, after Master, in Serial and Parallel. Output Mode is set on `[MIX]`,
where Split splits the buses (see Output Mode and Post effects).

**Crossfade Curve** sets how Crossfade behaves:

| Curve | Behaviour | Use |
|---|---|---|
| **Smooth** | constant perceived level across the sweep | slow fades |
| **DJ** | Bus A stays at 100% from 0 to 50, then fades linearly to 0 at 100. Bus B mirrors it. Both are at full level in the middle, like a DJ mixer crossfader | transitions (needed for the test project) |
| **Cut** | hard switch at the centre | stabs and instant swaps |

- Send and Crossfade are the performance controls. Per-bus levels are trims for
  setup, on page 2.
- **Mute / Solo** (Luca 2026-10-18, `[MIX]` page 3): Mute A / Mute B silence
  that bus at `[MIX]`. Solo A plays only Bus A, Solo B only Bus B. Solo
  overrides Mute. The effects keep running, so DSP load doesn't change.
- A control that does nothing in the current mode is disabled (shown as
  `—`): Send with Split input, Crossfade with Split output.
- Split and Mono Serial need a stereo input (PEDAL INPUT: STEREO). With a mono
  input they can't be picked; switching the input to mono falls back to
  Parallel (from Split) or Serial (from Mono Serial).
- If Send and Crossfade point at opposite buses (e.g. send only to A, crossfade only
  from B), the output is silent. A **!** badge shows on `[MIX]` and in its
  tab row when that happens (Parallel only, not with Split output).

> **Challenge (crossfade curves):** tune the three Crossfade curves and the Send
> curve so there is no unwanted dip or bump. Send keeps both buses at full
> level at the centre (true parallel).

> **Challenge (summing headroom):** adding two buses can clip, and the DJ
> curve has both buses at full level in the middle (about +3 dB for
> different material, up to +6 dB for identical material). DJ mixers handle
> this with plenty of internal headroom, a Master Level and level meters
> (meters are a future addition here), and
> leave the rest to the DJ (gain trims, cutting the bass of one side, which
> the test project already does). Same plan here: mix internally with
> headroom, set gain with the bus levels and Master Level, and add a safety
> limiter only on the final output. It stays even with the Mastering Limiter
> in Post: it is a simple, transparent catch for patches that don't use it.

> **Challenge (bus latency):** if one bus delays the sound more than the other
> (e.g. pitch effects), the sum will comb-filter. Find out whether bus delays
> can be measured and matched; Phase Invert helps the user check.

> **Challenge (DSP load):** parallel routing doesn't lower the processing
> load and stereo effects cost about twice as much as mono. The stock OS
> already has a budget: when it is exceeded the new effect is bypassed and
> "DSP Full" is shown (manual p.9). Measure whether 6 effects plus routing
> fit, and keep that same behaviour when they don't: the stock DSP FULL popup
> from the effect screen, and the bypassed effect drawn dotted with "FULL" as
> its second name line until enough DSP is freed.

### Old patches and new effects

- A patch saved before v2.0 loads in **Serial** mode with every effect in
  Pre, so it sounds exactly as before.
- A new effect is added in the same zone as the effect it is added next to
  (hold Cursor ◄ / ►; next to `[ROUTE]` or `[MIX]` it goes into the zone on that side).

### Serial modes

When `[ROUTE]` is set to a Serial mode, `[MIX]` and the A/B rows disappear
and all effects run in one line in this order, right to left: Pre, Bus A,
Bus B, Post. The A/B tags are hidden, but each effect **remembers its bus**,
so switching back to Parallel restores the layout.

| Mode | Signal |
|---|---|
| **Serial** | as stock: mono or stereo all the way, as the input |
| **Mono Serial** | stereo input only: L and R are summed to mono at `[ROUTE]`; everything after it runs mono (Pre still gets the stereo input) |

### Effect types and channel behaviour

Effects handle the two channels in four ways:

| Type | What it does to L/R | Examples |
|---|---|---|
| **Mono** | sums L+R, outputs the same on both sides | many stock drives and filters |
| **Mono in, stereo out** | sums L+R, then spreads it across both sides | ping-pong delays, wideners |
| **Stereo, linked** | keeps both sides but lets them affect each other | stereo reverbs, a linked stereo compressor (a peak on L also turns down R) |
| **Dual mono** | L and R processed fully separately | custom ZDLs that declare it |

> **Challenge (effect type):** the firmware must know each effect's type.
> Find out whether stock ZDLs declare it; otherwise keep our own chart of
> stock effects (to be checked together). Custom ZDLs declare it.

### Output Mode and Post effects

Post effects process one stereo pair after `[MIX]`. What they receive depends
on Output Mode:

| Output Mode | What `[MIX]` sends to Post | Post effects | At the jacks |
|---|---|---|---|
| **Stereo** | A + B summed as a stereo pair | behave normally | as processed |
| **Mono** | A + B summed as a stereo pair | behave normally | final mono sum after Post, so no Post effect can widen it again |
| **Split** | Bus A summed to mono on L, Bus B summed to mono on R | only **dual mono** effects keep the sides apart. Mono effects merge A and B; stereo-out and linked effects bleed one side into the other | as processed |

Split input works the same way for Pre effects: they sit before the split,
so anything but dual mono mixes L into R before `[ROUTE]` separates them.

### Smart Warning

**Status: maybe.** It depends on knowing each effect's type (see above).
Designed anyway, in the mockup.

Show a badge on an effect whenever its type breaks what the routing is set up
for:

| Where | Mode | Badge on |
|---|---|---|
| anywhere | stereo signal | Mono effects (they collapse stereo) |
| Pre | Split input | anything but dual mono |
| Post | Split output | anything but dual mono |

The badge only warns. The effect still runs, because bleeding on purpose can
be useful.

- **Effect Chain:** a filled **!** tag above the cover (where Serial A/B
  tags would go). Bus rows have no room above, so there the tag sits in the
  cover's top-left corner and the name moves right. With the cursor on the
  effect (nothing selected) the hint row shows the reason: `MONO FX ON
  STEREO`, `MIXES L INTO R` (Pre, Split input) or `MIXES A INTO B` (Post,
  Split output).
- **Knob pages:** a **!** tab in the tab row and the reason at the right of
  the hint row.

### MIDI

Every `[ROUTE]` and `[MIX]` parameter gets a CC (Send, Crossfade, levels, modes),
chosen so it doesn't clash with the current CC chart or the stock CC 74/75.
These are also the hooks Perform mode will use.

## Phase 3: Perform mode (draft design)

Ships in v2.0 together with Phases 1 and 2. A performance screen on top of
the normal pedal: the controls needed during a transition, on one screen.
Schematic: https://claude.ai/artifact/P6CPM86Vbke3YZQLM9V6tZ

### Getting in and out

- Two separate menu items: **PERFORM** (play) and **PERFORM SETUP**
  (assign controls). Setup is never reached from inside Perform mode,
  because there every control is taken.
- **Leaving:** the **up button always leaves**. It is the hardest button to
  reach with the foot, so it is the least useful one to assign.
- Inside, **HOLD FOR and the button combos are off**; every control belongs
  to Perform mode.
- **Leaving keeps everything:** moved values stay where they are, and
  pending actions and follows keep running.

### Principle: one control, one target, many gestures

Inspired by Loopy Pro's actions and follow actions. Each control is
assigned **one target** (one effect parameter, a node control or a looper
command). Several controls may share a target; one control never has two.
Each **gesture** on a control moves its target, and can schedule a
**follow** that happens later, on the grid. Only the footswitch's follows
can reach other targets.

### Targets

Picked from a list by name, for example `FX1 Knob 2`, `FX3 On/Off`,
`MIX Crossfade`, `ROUTE Send`, `LOOP Rec/Stop/Play`, `LOOP Roll`. Internally
each one is a MIDI CC (the existing chart plus the new `[ROUTE]` / `[MIX]` /
looper CCs), so the same targets can also be driven from a controller or a
DAW.

**Values are CC values (0-127).** Stepped targets (on/off, Type, modes) take
the step the CC value falls in, exactly as when the CC comes over MIDI; a
lag on a stepped target steps through the values on the way.

Targets are **by position** (`FX1` = effect 1 in the chain). Moving an effect
in the Effect Chain screen moves its assignments to whatever takes its place.
Known limitation, kept for simplicity.

### Gestures

| Control | Gestures |
|---|---|
| Knobs 1-3 | turn, press, double press, hold |
| Buttons down, left, right | press, double press, hold |
| Button up | reserved: **always leaves** Perform mode (not assignable) |
| Footswitch | press, double press, hold |

Release is part of Hold, not a gesture of its own.

- **Press waits only when it has to:** if Double or Hold are also set on that
  control, Press fires after the double-press window (about 300 ms);
  otherwise at once. Quantized actions hide the wait.
- **Knobs must never confuse turn, press and hold**, even with a brief
  accidental click while turning or a small turn while pressing.

> **Challenge (gesture recognizer) — hard:** a per-knob state machine with
> tuned thresholds, to be set on the real pedal:
> - a click shorter than ~30 ms is ignored (bounce, accidental bump);
> - while the knob is turning (a detent in the last ~150 ms), clicks are
>   ignored;
> - while the knob is held, 1 detent of movement is ignored (pushing an
>   encoder wobbles it); 2 or more detents cancel the press/hold and count
>   as a turn;
> - hold starts after ~400 ms held still; double press is two clicks within
>   ~300 ms.
> All thresholds are constants in one place, tested by hand on the pedal.

### Moves: value, when, lag

Every move (a gesture's **action**, Hold's **release**, any **follow**) has
four settings:

| Setting | Choices |
|---|---|
| **Value** | 0-127 (CC value) |
| **When** | IMMEDIATE · CLOCK · CYCLE · EVENT (footswitch only) |
| **Amount** | depends on When: none for Immediate; NEXT, 1 .. 16 beats or bars for Clock; 1 .. 16 bars for Cycle; loop recorded / stopped / deleted for Event |
| **Lag** | 0 · ms · s · beats · bars, one list from 0 up |

| Gesture | Action | Release | Follow |
|---|---|---|---|
| Turn | — (turning sets the value) | — | yes |
| Press, Double press | yes | — | yes |
| Hold | yes | yes | yes |

**When:**

| Choice | Means | Pressed in bar 6, "8 bars" lands |
|---|---|---|
| **Immediate** | now (for a Follow: right after the gesture) | — |
| **Clock NEXT** | the next beat or bar line (plain quantize) | — |
| **Clock N** | waits for the next line, then N **full** beats or bars; ignores the cycle | end of bar 14 |
| **Cycle N** | the next N-bar line of the song grid, which starts at MIDI Start (or the first looper press). Same as the looper's quantize | end of bar 8 |
| **On event** | footswitch follows only: loop recorded, loop stopped, loop deleted | — |

Without a MIDI clock and without a looper there is no cycle: the Cycle
choices are hidden.

**Lag** is how long the value takes to get there. A short lag (10-50 ms) is
a click-free jump; a long one is a fade.

**Follow** is counted from the **end of the gesture** for Turn (when you stop
turning) and Hold (when you release), and **from the start** of the action
for Press and Double press.

**Newest move wins:** a Follow or a new gesture that comes due while an
earlier move is still lagging takes over from wherever the value is. Two
controls on the same target work the same way; the screen always shows the
live value.

Example, knob 2 on the master high-pass:

| Gesture | Action (value · when · lag) | Release | Follow |
|---|---|---|---|
| Turn | — | — | 0 · Cycle 8 bars · 20 ms |
| Press | 70 · next bar · 20 ms | — | 0 · Clock 1 bar · 20 ms |
| Hold | 80 · immediate · 20 ms | 0 · immediate · 1 s | — |

Right button on the loop high-pass ("kill the low end over 4 bars, hold 4,
restore"): Action 100 · next bar · 4 bars; Follow 0 · Clock 8 bars · 20 ms
(counted from the press: 4 rising + 4 holding).

Not covered on purpose: a delay in ms or s before acting (use the grid for
timed things), and a fade that must end exactly on a cycle line (start on
the grid and set the lag in bars).

### Presets

A **preset** fills in all moves of a gesture (action, release, follow) in
one go. The last preset, **CUSTOM**, starts from scratch. Editing any field
of a preset turns it into CUSTOM.

| Preset | Fills in |
|---|---|
| **Throw** | to a value on the next bar, back after N bars |
| **Momentary** | hold: to a value while held, back on release |
| **Drop at cycle end** | turn: back to 0 at Cycle N bars |
| **Fade** | to a value over N bars |
| **Toggle** | between two values |
| **Custom** | defaults: immediate, lag 20 ms, no follow |

### Setup screen for one gesture

Knob order: preset, value, when, amount, lag. Three knobs per page, knob 3 press turns the page, like an effect's edit
screen:

| Page | Knob 1 | Knob 2 | Knob 3 |
|---|---|---|---|
| Action 1 | Preset | Value | When |
| Action 2 | Amount | Lag | — |
| Release (hold only), Follow | Value | When | Amount |
| ... page 2 | Lag | — | — |

### Footswitch

The footswitch's gestures can each have **their own target**, and its
follows can reach **other targets** and wait for **events**. That makes it
the conductor of a transition: start the loop, then let the crossfade
follow by itself.

### Looper as a target

The looper takes **commands** instead of values: `LOOP Rec/Stop/Play`
(record when empty, otherwise stop or play at the next grid line),
`LOOP Delete`, `LOOP Roll` (the roll rate, as a value). Any control can
target the looper (for example a button that holds Roll at 1/16).

Default footswitch in a patch with a looper:

| Gesture | Action | Follow |
|---|---|---|
| Press | `LOOP Rec/Stop/Play` (records only when empty) | on event loop recorded: `MIX Crossfade` to 127 (loop only) |
| Double press | `LOOP Delete` | — |
| Hold | free | — |

> **Challenge (timing precision):** the jump to the loop must land exactly
> on the sample where recording ends and the loop starts, or the listener
> hears a gap or a doubled beat. Quantized actions have to be executed on
> the audio side at the grid line, not whenever the UI task gets to them.
> Smoothing jumps internally so they don't click is up to the
> implementation; it is not a user setting.

### Reference use case: the transition

The setup this design must support, step by step (8-bar cycle, MIDI clock
from a Digitakt):

| Control | Target | Turn | Press | Double press | Hold |
|---|---|---|---|---|---|
| Footswitch | looper | — | rec / stop / play; on loop recorded: Crossfade jumps to loop only | delete | — |
| Knob 1 | `MIX Crossfade` | crossfade live ↔ loop | to 50 at the next grid line | to live only | — |
| Knob 2 | master high-pass cutoff | up; back to 0 at the end of the 8-bar cycle | 70 for 1 bar, then 0 | — | 80 while held, 0 on release |
| Knob 3 | washout send | up; back to 0 at the end of the 8-bar cycle | 70 for 1 bar, then 0 | — | 80 while held, 0 on release |
| Right button | loop high-pass cutoff | — | glide up over 4 bars, hold 4 bars, back to 0 | — | glide up over 1 bar, hold, back to 0 on release |

1. Playing the Digitakt, press the footswitch. At bar 6 or at bar 3 alike,
   recording waits for the end of the 8-bar cycle, then records 8 bars
   (Crossfade at 50: the live sound is heard in full).
2. Change pattern on the Digitakt; it waits for its own 8 bars.
3. At the cycle line the recording ends, Crossfade jumps to loop only, and the
   Digitakt changes pattern. The listener hears the loop restart, nothing
   else. Left alone, the loop plays forever.
4. Knob 1 brings live elements back in slowly; press = back to 50 on the
   grid; double press = live only.
5. Knobs 2 and 3 throw the master high-pass and the washout; they fall back
   to 0 by themselves when the 8-bar cycle ends, so the drop is hands-free.
6. Right button: the loop's low end is slowly killed for 4 bars, held for 4,
   then restored.
7. Footswitch: the loop stops at the next grid line. Double press deletes it.

### Transport and patches

| Event | Effect on Perform mode |
|---|---|
| MIDI Start or Stop | resets everything: pending actions and follows are cancelled, the grid restarts |
| Tempo change | everything adapts: beat and bar times follow the new tempo |
| Patch change | resets everything |

### Feedback: looper and cycle state

The stock firmware shows nothing of this, so it is new. Shown at all times
in Perform mode (and on the looper's own screen):

| What | How |
|---|---|
| **Where in the cycle** | a bar strip (one segment per bar of the cycle, filled up to the current bar) and the beat |
| **Looper state** | EMPTY · RECORDING · PLAYING · STOPPED · ROLLING, with the loop length |
| **What is about to happen** | a countdown for anything waiting on the grid: `REC IN 2 BARS`, `DELETE IN 3 BEATS`, `STOP AT CYCLE END`. It **pulses, faster and faster** as the moment comes |
| **Pending follows** | a small mark next to any control with a follow waiting |
| **Footswitch LED** | see the table below |

| Looper state | Footswitch LED |
|---|---|
| Empty | off |
| Waiting (to record, stop, play or delete) | a countdown blink that speeds up as the moment comes (below) |
| Recording | slow pulse |
| Playing | on |
| Stopped (loop kept, silent) | off (the screen shows STOPPED) |
| Rolling | on, like playing |

**Countdown blink:** the blink rate doubles each time the remaining time
halves, locked to the grid. For example, 8 bars before: one blink per bar
for the first 4 bars, then 8th notes for 2 bars, faster again in the next
bar, 16ths in the last bar, 32nds in the last beat. The exact steps get
tuned on the pedal; the screen countdown pulses the same way.

> **Challenge (looper state to the screen):** the looper is an effect; the
> screen is drawn by the firmware. The looper must publish its state and
> pending action somewhere the firmware can read (the reverse of the tempo
> transport block the pack effects already read). Check that the footswitch
> LED can be driven freely.

### Screen

Target names and live values for the three knobs, the button targets, the
footswitch's gestures, and the feedback strip above.

### Setup

From **PERFORM SETUP** in the menu: pick the control, pick its target,
then set each gesture on the pages above (preset first). Learn is left for
later.

Assignments are **saved per patch**.

> **Challenge (patch memory):** about 600 bytes of assignments per patch
> (8 controls × 4 gestures × 3 moves), ~30 KB for 50 patches. Add it to the
> patch storage challenge.
